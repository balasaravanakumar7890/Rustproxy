# RustProxy Security Model & Safety Boundary

`RustProxy` is engineered strictly as a defensive, authorized security auditing and development platform. This document defines the operational boundaries, data safety principles, and controls implemented to ensure responsible, authorized use.

---

## 1. Safety Principles & Operational Scope

1. **Explicit Target Authorization & Scope Enforcement**:
   - `RustProxy` implements strict scope rules. Operators can define whitelist filters (e.g., `*.local`, `127.0.0.1`, `dev.mycompany.internal`).
   - Requests targeting destinations outside the defined scope can be automatically bypassed, logged in a pass-through mode without deep inspection, or blocked entirely.
2. **Defensive Analysis Only**:
   - The platform focuses on passive analysis, protocol diagnostics, header validation (CSP, HSTS, secure cookies), and manual inspection.
   - It strictly excludes automated destructive attacks, weaponized exploit generation, or unauthorized brute-force fuzzing.
3. **Local Trust Boundary**:
   - The Root CA generated by `RustProxy` is unique to every user installation.
   - The private key of the generated CA is stored locally with restricted file permissions (`chmod 0600`) and is never transmitted over the network.
   - The proxy listener defaults strictly to `127.0.0.1` (loopback interface) to prevent external or unauthorized machines from utilizing the proxy or intercepting traffic.

---

## 2. Sensitive Data & Privacy Protection

1. **Credential Masking**:
   - The logger can be configured to mask sensitive headers (such as `Authorization: Bearer ...` or `Cookie: session=...`) when exporting traffic traces or capturing screenshots.
2. **Local Persistence Encryption & Ephemerality**:
   - Storage uses local SQLite databases stored in the user's project directory or an optional in-memory mode (`:memory:`) for ephemeral auditing sessions where data should not persist to disk.
3. **Extension Sandboxing**:
   - User plugins run within a WebAssembly sandbox with restricted capabilities, preventing unauthorized disk access, network exfiltration, or environment variable inspection.
